# Lite Mode Implementation Plan (MVP follow-up: 1-command run)

> **Why:** competitors run in one command (Open WebUI: 1 container, SQLite
> default); Orivory needs 10 services + ~40 env vars. Our own user research
> ranked setup friction as a top-3 pain. Decision (founder, 2026-09-04):
> Option A — full lite mode.

**Goal:** `docker run -d -p 8000:8000 -v orivory-data:/data -e OPENAI_API_KEY=sk-… ghcr.io/twilightt1/orivory:latest` boots the full memory hub (API + MCP) with **zero external services**: SQLite storage, in-process Chroma, in-memory caches, eager tasks, filesystem uploads.

**Non-goals:** replacing Postgres in the full compose stack; serving the Next.js UI inside the lite container (API + MCP only — the ICP is agents); multi-user lite mode.

## Tasks

### Task 1 — Cross-dialect models + SQLite bootstrap
- `app/models/*.py`: `UUID(as_uuid=True)` → `sa.Uuid()`, `ARRAY(String)` → `sa.JSON`, `JSONB` → `sa.JSON`, `EncryptedJSONB.impl` → `sa.JSON`, `server_default=text("gen_random_uuid()")` → python `default=uuid.uuid4`, gin-index hints behind a postgres guard.
- `app/database.py`: engine supports sqlite+aiosqlite; `bootstrap_sqlite()` = `Base.metadata.create_all` (alembic stays postgres-only).
- `app/config.py`: `DATABASE_URL` optional → defaults `sqlite+aiosqlite:////data/orivory.db` when `LITE_MODE=1`.
- Tests: `tests/lite/test_sqlite_bootstrap.py` — create_all on aiosqlite memory DB, create user + memory + agent client, query back. Verify every model.

### Task 2 — Optional Redis + eager tasks
- `app/redis_client.py`: `get_redis()` returns `InMemoryRedis` when `REDIS_URL == ""` (dict-based async fake lifted from the test fakes; supports get/set/setex/incr/expire/delete/ping/scan-iter used by middlewares).
- `app/config.py`: `LITE_MODE` drives `task_always_eager`; celery worker/beat/flower are compose-profile-only.
- Tests: rate limiter + retrieval cache behave on InMemoryRedis.

### Task 3 — Chroma local mode + filesystem storage
- `vector_store.py`: `CHROMA_MODE=local` → `chromadb.PersistentClient(path=data/chroma)`; async callers route through the sync client (lite = single user).
- `app/storage.py`: `STORAGE_BACKEND=fs` → local `data/uploads` implementing the same ensure/put/get/delete surface as the MinIO path.
- Tests: both modes with fakes/tmp dirs.

### Task 4 — All-in-one image + quickstart
- `Dockerfile.lite` (python:3.13-slim, uvicorn, /data volume) or a `lite` target in Dockerfile; `.github/workflows/docker-publish.yml` → GHCR on main merges + tags.
- `Makefile`: `make quickstart`; README: two run paths (lite 1-liner / full compose); `docs/ROADMAP.md` update.
- Verify: `docker build -f Dockerfile.lite .` + container boots `/health`, `/ready`, `/mcp` reachable; sqlite file created in volume.
